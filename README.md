## Задание и принятые решения

Фильтры применяются K раз. Получаются две независимые результирующие матрицы: K эрозий исходной матрицы и K наращиваний исходной матрицы. Эрозия выбирает минимум, наращивание — максимум в квадратном окне 3 × 3. За границами учитываются только существующие элементы.

В тексте варианта размер окна и обработка границ не конкретизированы; окно 3 × 3 и его обрезка по границам являются выбранными правилами реализации. Это не медианный фильтр и не последовательность «эрозия, затем наращивание».

Размеры, число проходов и предел потоков задаются параметрами. Матрица генерируется детерминированно с начальным состоянием 12, значения имеют тип double и лежат в диапазоне 0,0–99,9. Ввод произвольной матрицы из файла в этой реализации не предусмотрен.

## Сборка и запуск в Debian

Нужны GCC и GNU Make; для диагностики — procps и strace. Все команды ниже выполняются в Linux-терминале. VS Code открывается через подключение WSL: Debian.

```bash
make
./lab3 -r 3 -c 3 -k 2 -t 3 -p -v
```

`make clean` удаляет main.o, filter.o и lab3. Файлы исходного кода и результаты опытов сохраняются.

| Ключ | Назначение | По умолчанию |
|---|---|---|
| `-r` | Число строк, положительное целое | 3 |
| `-c` | Число столбцов, положительное целое | 3 |
| `-k` | Число проходов, положительное целое | 1 |
| `-t` | Максимум потоков, включая основной | 1 |
| `-p` | Печать исходной и результирующих матриц | выключено |
| `-v` | PID/TID, номер прохода, диапазон строк | выключено |
| `-h` | Справка | — |

Число участников равно min(предел потоков, число строк). Основной поток считает свой диапазон, остальные создаются pthread_create. На каждом проходе выполняются pthread_join, затем меняются местами входной и выходной буферы. Между проходами рабочие потоки создаются заново. При `-t 1` дополнительные потоки не создаются.

Потоки читают общие входные буферы и записывают непересекающиеся строки выходных буферов. Мьютекс для элементов матриц не нужен. Ожидание join перед обменом буферов обеспечивает завершение прохода и видимость результатов.

## Количество потоков средствами ОС

```bash
./lab3 -r 2000 -c 2000 -k 100 -t 4 > checks/thread_run.txt 2>&1 &
lab_pid=$!
sleep 0.2
ps -L -p "$lab_pid" -o pid,tid,nlwp,comm
wait "$lab_pid"
```

NLWP показывает текущее число потоков процесса, TID — идентификатор каждого. В короткие промежутки создания и завершения потоков NLWP может быть меньше заданного предела. Сохранённый опыт: checks/threads.txt, screenshots/threads_ps.png.

## Трассировка

```bash
strace -f -tt -e trace=clone,clone3,futex -o checks/strace.txt ./lab3 -r 512 -c 512 -k 2 -t 3 -v
head -n 30 checks/strace.txt
```

clone3 создаёт потоки; CLONE_VM означает общую виртуальную память, CLONE_THREAD — принадлежность к одной группе потоков. futex используется библиотекой при ожидании. EAGAIN при FUTEX_WAIT_BITSET может означать изменение ожидаемого значения до начала сна; это обрабатывается внутри библиотеки и само по себе не означает ошибку программы.

## Исследование производительности

```bash
bash benchmark.sh
```

Внимание: сценарий заменяет checks/timings.tsv новыми замерами. Сохранённые исходные данные опыта от 27.10.2026 продублированы в report/timings_original.tsv.

Использованы размеры 128 × 128, 512 × 512 и 2000 × 2000; K = 10; 1, 2, 4, 8 и 12 потоков. После прогрева проведено по три измерения, взята медиана. Таймер CLOCK_MONOTONIC включает обработку, создание и ожидание потоков; генерация данных и печать матриц исключены. Для исследования не включайте -p, -v, strace или санитайзеры.

Ускорение S(p) = T(1)/T(p), эффективность E(p) = S(p)/p. Сводка: report/summary.tsv. На матрице 2000 × 2000 медианное ускорение при 12 потоках — 3,650; эффективность — 30,4%. На 128 × 128 потоки замедляют расчёт из-за накладных расходов.
